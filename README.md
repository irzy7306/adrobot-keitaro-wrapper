# Adrobot — обёртка над Keitaro

Тестовое задание: создание кампаний Keitaro с двумя потоками и редактирование офферов в существующих кампаниях.

**Стек:** FastAPI, SQLAlchemy 2, Alembic, PostgreSQL, React, TypeScript и обычный CSS. **Без Tailwind CSS.**

## Запуск через Docker

1. Установите Docker и Docker Compose v2.
2. Создайте файл переменных окружения:

   ```bash
   cp .env.example .env
   ```

3. Откройте `.env`, укажите `KEITARO_API_KEY` из раздела Admin API в Keitaro и замените `CAMPAIGN_PREFIX=test_raznitsina_` (уже установлен). Для совместимости с URL лучше использовать фамилию латиницей в нижнем регистре, например `test_raznitsina_`.
4. Соберите и запустите контейнеры:

   ```bash
   docker compose up --build -d
   ```

5. Примените миграции базы данных:

   ```bash
   docker compose exec backend alembic upgrade head
   ```

6. Откройте приложение:
   - **Веб-интерфейс:** http://localhost:5173
   - **Swagger-документация backend API:** http://localhost:8000/docs

Остановка контейнеров:

```bash
docker compose down
```

Полная очистка локальной базы данных (все данные в Docker volume будут удалены):

```bash
docker compose down -v
```

## Миграции базы данных

Применить все миграции:

```bash
docker compose exec backend alembic upgrade head
```

Откатить последнюю миграцию:

```bash
docker compose exec backend alembic downgrade -1
```

Создать новую миграцию после изменения SQLAlchemy-моделей:

```bash
docker compose exec backend alembic revision --autogenerate -m "описание изменений"
```

**Важно:** перед применением автоматически сгенерированной миграции проверьте её содержимое.

## Локальный запуск без Docker

### Backend

Нужны Python, PostgreSQL и установленные зависимости.

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Запустите PostgreSQL отдельно. Укажите параметры подключения и API-ключ Keitaro в переменных окружения либо в конфигурации проекта:

```bash
export DATABASE_URL='postgresql+psycopg://adrobot:adrobot@localhost:5432/adrobot'
export KEITARO_API_KEY='ваш-api-ключ'
alembic upgrade head
uvicorn app.main:app --reload
```

Для Windows вместо `source .venv/bin/activate` используйте соответствующую команду активации виртуального окружения, а вместо `export` — синтаксис вашей оболочки.

### Frontend

В отдельном терминале:

```bash
cd frontend
npm install
npm run dev
```

При запуске вне Docker измените целевой адрес прокси в `frontend/vite.config.ts` на `http://localhost:8000`. Внутри Docker используется адрес `backend:8000`.

## Функциональность

### 1. Создание кампаний

Форма принимает название кампании, двухбуквенный GEO-код страны, ID оффера (выбирается из списка), домен, группу и источник трафика.

Создаётся кампания с двумя потоками в заданном порядке приоритета:

1. Поток с GEO-фильтром: посетители из выбранной страны перенаправляются на Google.
2. Обычный поток: остальные посетители направляются на указанный оффер.

### 2. Редактирование кампаний

Можно просматривать существующие кампании, выбирать поток с офферами, видеть текущие привязки, добавлять и удалять офферы. После каждого изменения приложение повторно запрашивает данные потока из Keitaro.

### 3. Статистика

Приложение запрашивает отчёт Keitaro с группировкой по потокам и офферам за выбранный период. Результат намеренно отображается в формате JSON, без самостоятельно вычисленных итогов: состав и названия полей отчёта могут отличаться в разных версиях трекера.

### 4. Локальная база данных

PostgreSQL хранит связи с созданными кампаниями и небольшой журнал операций. **Источником актуальных настроек кампаний остаётся Keitaro.**

### 5. Обработка ошибок и безопасность

- API-ключ хранится только в backend-конфигурации и не передаётся во frontend.
- Секреты не должны попадать в Git; файл `.env` не публикуется.
- Повторное добавление уже привязанного оффера блокируется.
- При частичном сбое создания кампании приложение пытается отключить созданную кампанию.

## Маршруты backend API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | Проверка состояния сервиса |
| `GET` | `/api/options` | Списки доступных доменов, групп, источников и офферов |
| `GET` | `/api/campaigns` | Список кампаний |
| `GET` | `/api/campaigns/{id}` | Кампания и её потоки |
| `POST` | `/api/campaigns` | Создание кампании с двумя потоками |
| `POST` | `/api/campaigns/{id}/offers` | Добавление оффера в поток |
| `DELETE` | `/api/campaigns/{id}/offers/{offer_id}` | Удаление оффера; `stream_id` передаётся в JSON-теле запроса |
| `POST` | `/api/campaigns/{id}/stats` | Получение отчёта Keitaro |

## Особенности интеграции и известные ограничения

- **Работа с предоставленным реальным инстансом Keitaro ещё не проверена.** API-ключ не включён в проект: его необходимо самостоятельно получить в админке и указать в `.env`.
- Контракт Admin API зависит от версии Keitaro. Перед проверкой на реальном инстансе следует сверить параметры фильтра и тип редиректа (`action_type`) в `POST /streams`, типы групп в `GET /groups`, а также метрики и фильтры в `/report/build` со Swagger-документацией конкретной установки.
- Официальная документация: https://admin-api.docs.keitaro.io/.
- Количество привязанных офферов не берётся из локального кеша. Статистика выводится как исходный ответ Keitaro, чтобы не показывать ошибочно интерпретированные значения.
- Это прототип для тестового задания, а не готовая production-система. Для промышленного использования потребуются авторизация и разграничение прав, при необходимости CSRF-защита, ограничение частоты запросов, интеграционные тесты и более надёжная обработка повторов и частичных сбоев.
